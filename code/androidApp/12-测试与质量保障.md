# 12 测试与质量保障：单测、协程测试、UI 测试和线上稳定性

> 测试的目标不是追求数字，而是让核心逻辑、数据迁移、异步状态、页面交互和发布质量可验证。

---

## 1. 测试金字塔

```text
少量端到端测试
中等数量 UI / 集成测试
大量单元测试
```

App 项目优先覆盖：

- ViewModel 状态流。
- UseCase 业务规则。
- Repository 缓存策略。
- Room migration。
- 关键 Compose 页面交互。
- 登录、支付、下单等核心路径。

---

## 2. ViewModel 单测

```kotlin
@OptIn(ExperimentalCoroutinesApi::class)
class MainDispatcherRule(
    private val dispatcher: TestDispatcher = StandardTestDispatcher(),
) : TestWatcher() {
    override fun starting(description: Description) {
        Dispatchers.setMain(dispatcher)
    }

    override fun finished(description: Description) {
        Dispatchers.resetMain()
    }
}
```

测试：

```kotlin
class LoginViewModelTest {
    @get:Rule
    val mainDispatcherRule = MainDispatcherRule()

    @Test
    fun loginSuccessNavigatesHome() = runTest {
        val repository = FakeLoginRepository(result = LoginResult.Success)
        val viewModel = LoginViewModel(repository)

        viewModel.login("user", "password")
        advanceUntilIdle()

        assertThat(viewModel.uiState.value.loading).isFalse()
    }
}
```

## 3. Flow 测试

推荐 Turbine：

```kotlin
@Test
fun observeUserEmitsUpdatedUser() = runTest {
    repository.observeUser("1").test {
        assertThat(awaitItem()).isEqualTo(User(id = "1", name = "old"))
        repository.refreshUser("1")
        assertThat(awaitItem()).isEqualTo(User(id = "1", name = "new"))
        cancelAndIgnoreRemainingEvents()
    }
}
```

重点：

- 用 `runTest` 控制虚拟时间。
- 避免真实 delay。
- 取消收集，防止测试挂起。

## 4. Repository 测试

```kotlin
class UserRepositoryTest {
    private val api = FakeUserApi()
    private val dao = FakeUserDao()
    private val repository = RealUserRepository(api, dao)

    @Test
    fun refreshStoresRemoteUser() = runTest {
        api.user = UserDto(id = "1", name = "Ada")

        repository.refreshUser("1")

        assertThat(dao.user("1")?.name).isEqualTo("Ada")
    }
}
```

不要为了 mock 而 mock。简单 fake 往往更稳定、更容易读。

## 5. Room migration 测试

```kotlin
@RunWith(AndroidJUnit4::class)
class MigrationTest {
    @get:Rule
    val helper = MigrationTestHelper(
        InstrumentationRegistry.getInstrumentation(),
        AppDatabase::class.java,
    )

    @Test
    fun migrate1To2() {
        helper.createDatabase(TEST_DB, 1).apply { close() }
        helper.runMigrationsAndValidate(TEST_DB, 2, true, MIGRATION_1_2)
    }
}
```

数据库迁移必须测，因为一旦线上迁移失败，用户可能直接打不开 App。

## 6. Compose UI 测试

```kotlin
@get:Rule
val composeRule = createComposeRule()

@Test
fun clickLoginShowsLoading() {
    composeRule.setContent {
        LoginScreen(
            state = LoginUiState(),
            onLogin = {},
        )
    }

    composeRule.onNodeWithText("Login").performClick()
    composeRule.onNodeWithText("Login").assertExists()
}
```

建议给关键节点加语义：

```kotlin
Modifier.semantics { contentDescription = "login_button" }
```

## 7. Espresso 测试

View 系统项目仍常用 Espresso：

```kotlin
@Test
fun openDetail() {
    onView(withId(R.id.recyclerView))
        .perform(RecyclerViewActions.actionOnItemAtPosition<UserViewHolder>(0, click()))

    onView(withText("Detail"))
        .check(matches(isDisplayed()))
}
```

混合项目可能同时需要 Espresso 和 Compose Test。

## 8. Robolectric

Robolectric 适合 JVM 上跑部分 Android 逻辑：

```kotlin
@RunWith(RobolectricTestRunner::class)
class FormatterTest {
    @Test
    fun formatsStringResource() {
        val context = ApplicationProvider.getApplicationContext<Context>()
        assertThat(context.getString(R.string.app_name)).isNotEmpty()
    }
}
```

注意：Robolectric 不是完整设备环境，和 Framework 真实行为可能有差异。

## 9. 线上质量保障

需要建设：

- Crash 收集。
- ANR 收集。
- 关键链路日志。
- 性能指标。
- 灰度发布。
- 版本回滚。
- mapping 归档。
- 用户反馈定位信息。

日志建议带业务上下文，但不要打印 token、手机号、身份证、精确位置等敏感信息。

---

## 10. 常见问题

| 问题 | 建议 |
|---|---|
| 单测依赖 Android 环境 | 抽接口，移动到 pure Kotlin 层 |
| 协程测试偶发失败 | 使用 `runTest` 和 TestDispatcher |
| UI 测试不稳定 | 等待条件明确，减少动画和真实网络 |
| Mock 太多难维护 | 用 fake/in-memory 实现 |
| 线上堆栈不可读 | 保存 mapping 并自动还原 |

## 11. 源码查看建议

| 主题 | 源码入口 |
|---|---|
| 协程测试 | `kotlinx.coroutines.test` |
| Compose 测试 | `androidx.compose.ui.test` |
| Espresso | `androidx.test.espresso` |
| Robolectric | Robolectric shadows |
| LeakCanary | Shark heap graph |

测试源码可以晚一点看，但测试失败时要能理解调度器、主线程、IdlingResource 和虚拟时间。
