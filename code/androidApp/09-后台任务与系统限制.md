# 09 后台任务与系统限制：WorkManager、JobScheduler、Alarm、前台服务

> 后台任务是 Android App 最容易和系统策略冲突的地方。代码写对了不代表一定会按时执行，还要考虑 Doze、Standby、后台启动限制、电池优化和厂商策略。

---

## 1. 先选对后台方案

| 场景 | 推荐方案 |
|---|---|
| 可延迟、要可靠完成 | WorkManager |
| 系统级周期/约束任务 | JobScheduler |
| 准点提醒 | AlarmManager |
| 用户可感知持续任务 | Foreground Service |
| 服务端实时消息 | FCM / 厂商推送 |
| 页面内短任务 | `viewModelScope` / lifecycle scope |

原则：不要用 Service 当万能后台线程。

## 2. WorkManager

```kotlin
class UploadWorker(
    appContext: Context,
    params: WorkerParameters,
    private val repository: UploadRepository,
) : CoroutineWorker(appContext, params) {
    override suspend fun doWork(): Result {
        val fileId = inputData.getString("fileId") ?: return Result.failure()
        return when (repository.upload(fileId)) {
            UploadResult.Success -> Result.success()
            UploadResult.Retryable -> Result.retry()
            UploadResult.Fatal -> Result.failure()
        }
    }
}
```

入队：

```kotlin
val request = OneTimeWorkRequestBuilder<UploadWorker>()
    .setInputData(workDataOf("fileId" to fileId))
    .setConstraints(
        Constraints.Builder()
            .setRequiredNetworkType(NetworkType.CONNECTED)
            .setRequiresBatteryNotLow(true)
            .build(),
    )
    .setBackoffCriteria(BackoffPolicy.EXPONENTIAL, 30.seconds)
    .build()

WorkManager.getInstance(context).enqueueUniqueWork(
    "upload-$fileId",
    ExistingWorkPolicy.KEEP,
    request,
)
```

源码入口：

- `WorkManagerImpl`
- `Processor`
- `WorkerWrapper`
- `SystemJobScheduler`

## 3. PeriodicWorkRequest 不保证准点

```kotlin
val request = PeriodicWorkRequestBuilder<SyncWorker>(6, TimeUnit.HOURS)
    .setConstraints(Constraints(requiredNetworkType = NetworkType.CONNECTED))
    .build()
```

周期任务会受系统调度影响。它适合同步、清理、预取，不适合闹钟类准点提醒。

## 4. AlarmManager

普通定时：

```kotlin
alarmManager.setWindow(
    AlarmManager.RTC_WAKEUP,
    triggerAtMillis,
    10.minutes.inWholeMilliseconds,
    pendingIntent,
)
```

精确闹钟：

```kotlin
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S && !alarmManager.canScheduleExactAlarms()) {
    startActivity(Intent(Settings.ACTION_REQUEST_SCHEDULE_EXACT_ALARM))
} else {
    alarmManager.setExactAndAllowWhileIdle(
        AlarmManager.RTC_WAKEUP,
        triggerAtMillis,
        pendingIntent,
    )
}
```

Android 12+ 精确闹钟权限更严格。普通业务不要滥用 exact alarm。

## 5. 前台服务

适合导航、运动记录、录音、通话、文件传输等用户可感知任务。

```kotlin
class TrackingService : Service() {
    override fun onCreate() {
        super.onCreate()
        startForeground(NOTIFICATION_ID, createNotification())
    }

    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        startTracking()
        return START_STICKY
    }

    override fun onBind(intent: Intent): IBinder? = null
}
```

注意：

- Android 8+ 后台启动普通 Service 会受限。
- `startForegroundService()` 后必须及时 `startForeground()`。
- Android 14+ 前台服务类型和权限要匹配。

## 6. Doze 和 App Standby

Doze 下系统会延迟网络、wakelock、job、alarm。

排查命令：

```bash
adb shell dumpsys deviceidle
adb shell dumpsys jobscheduler package.name
adb shell dumpsys alarm package.name
adb shell am set-standby-bucket package.name restricted
```

用户说“锁屏后不执行”，通常要看：电池优化、待机桶、网络约束、厂商后台管理。

## 7. 后台启动 Activity 限制

后台进程不能随便弹 Activity。常见替代：

- 发通知，让用户点击进入。
- 使用全屏 Intent，但仅限来电、闹钟等高优先级场景。
- 等应用回前台再导航。

通知 PendingIntent：

```kotlin
val contentIntent = PendingIntent.getActivity(
    context,
    0,
    Intent(context, DetailActivity::class.java),
    PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE,
)
```

## 8. 推送和后台同步

推送到达后不要直接做大量工作。推荐：

```kotlin
class AppMessagingService : FirebaseMessagingService() {
    override fun onMessageReceived(message: RemoteMessage) {
        val work = OneTimeWorkRequestBuilder<SyncWorker>()
            .setInputData(workDataOf("reason" to "push"))
            .build()
        WorkManager.getInstance(this).enqueue(work)
    }
}
```

推送只是唤醒入口，可靠执行仍交给 WorkManager 或前台服务。

## 9. 常见问题

| 问题 | 优先排查 |
|---|---|
| Work 不执行 | 约束、待机桶、WorkManager 数据库、调度器 |
| 周期任务不准 | 系统批处理、Doze、Standby |
| 闹钟不响 | exact alarm 权限、Doze、PendingIntent |
| 前台服务启动失败 | 后台限制、通知权限、service type |
| 锁屏后断连 | Doze、厂商后台、网络保活策略 |

---

## 10. 和 Framework 文档怎么对照

- WorkManager 最终常落到 JobScheduler。
- AlarmManager 对应 Framework 的 AlarmManagerService。
- 前台服务对应 AMS 的 ActiveServices 和 NotificationManagerService。
- 后台限制对应 PowerManagerService、DeviceIdleController、AppStandby。
- 广播唤醒对应 AMS BroadcastQueue。

App 侧遇到“为什么没执行”，不要只看业务代码，要顺着系统服务状态查。
