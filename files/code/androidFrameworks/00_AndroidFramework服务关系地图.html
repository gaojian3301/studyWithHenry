② 核心服务协作链路

一条主线

一次 App 界面从"请求"到"上屏"，以及用户"触摸"回到 App，走的正是这一条链。

▸ 界面启动链路（startActivity → 上屏）
ATMS决定 Activity/Task/生命周期▶ AMS确保进程存在 · OOM/ANR▶ WMS加窗口 · 层级 · 焦点 · Insets▶ SurfaceFlinger合成 Layer · VSYNC · 上屏
▸ 输入回传链路（触摸 → 回到 App 处理）
InputReader/Dispatcher读事件 · 决定给谁▶ WMS 焦点窗口触摸命中▶ Looper/Handler事件回调进 App 主线程▶ HWUI/RenderThread重绘 → BufferQueue▶ SurfaceFlinger重新合成上屏

③ 各篇文档的关系网络

每一篇卡片 = 核心服务 + 它指向谁

④ 四阶段学习路线

引自学习顺序推荐

从"系统怎么启动、服务怎么通信"起步，到"窗口/显示/输入"，再到"权限/后台/电源"，最后是"系统UI/多用户/媒体"。

▸ 阶段二 · 包 / 进程 / 四大组件：04 PMS → 05/06 AMS → 10 ATMS → 07 Service · 08 广播 · 09 Provider

▸ 阶段四 · 权限 / 后台 / 电源 / UI / 媒体：14 权限 → 15 Power → 16 后台 → 17 通知 → 18 SystemUI → 19 多用户 → 20 相机 · 21 Audio
