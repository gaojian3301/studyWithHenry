## 1. 一句话建立直觉

**Transformer 的本质，就是一个"看上下文、猜下一个词"的机器。**

给它前文，它输出下一个最可能出现的词，再把这个词接上去，继续猜下一个——这样一句一句地"生成"出整段话。你现在用的大模型（ChatGPT、文心一言、DeepSeek 等），底层都是这个思路的变体。

它最核心的发明叫**注意力机制（Attention）**：一句话里的每个词，都能"看到"整句话里所有其他词，并判断**谁跟自己最相关**。就这么简单，剩下的都是围绕这个核心搭的脚手架。

---

## 2. 为什么以前的方案不行

在 Transformer（2017 年）之前，处理文字的主流是 **RNN / LSTM**，它的工作方式像**串行读磁带**：

```
读 "我" → 记住 → 读 "爱" → 更新记忆 → 读 "你" → 更新记忆 → ...
```

它有三大毛病：

1. **串行，慢**：必须一个词一个词地读，没法并行。GPU 有再多核也用不上。
2. **记不住长距离**：句子一长，读到后面就把开头忘了（梯度消失）。
3. **顺序敏感**：它天然假设"离得近的相关"，但语言里"远距离的指代"很多。

Transformer 的答案很直接：

- **并行**：所有词**同时**参与计算，不再串行。
- **注意力**：每个词直接和所有词连线，距离再远也能"一眼看到"。

> 编程类比：RNN 像一条单线程的 `for` 循环，Transformer 像一次 `map` 全量并行处理 + 一个"相关性矩阵"。

## 3. 整体架构

最经典的 Transformer 是一个 **Encoder-Decoder（编码器-解码器）** 结构，专门为**翻译**这类"输入一个序列、输出另一个序列"的任务设计：

```
输入：  "I love you"
  │
  ▼
┌─────────────────────────┐
│   Encoder（编码器）       │   读懂输入，把意思压缩成"中间表示"
│   × N 层                 │
└─────────────────────────┘
  │   中间表示（编码后的语义向量）
  ▼
┌─────────────────────────┐
│   Decoder（解码器）       │   看着中间表示，一个词一个词地吐出来
│   × N 层                 │
└─────────────────────────┘
  │
  ▼
输出：  "我 爱 你"
```

- **Encoder**：负责"**理解**"。把输入句子读进去，产出一堆"装满了上下文信息"的向量。
- **Decoder**：负责"**生成**"。根据 Encoder 的理解 + 已经生成的内容，吐出下一个词。

后面你会看到，Encoder 和 Decoder 内部其实长得差不多，都是由**一堆相同的"积木块"叠起来**（论文里叠了 6 层，`N=6`）。

## 4. 词嵌入 Embedding

计算机不认识字，只认识数字。所以第一步：**把每个词变成一个向量**（一串数字）。

```
"猫"  →  [0.21, -0.34, 0.87, ..., 0.05]   （比如 512 维的向量）
"狗"  →  [0.18, -0.30, 0.85, ..., 0.02]
"苹果" →  [0.52, 0.11, -0.23, ..., 0.61]
```

神奇之处在于：**语义相近的词，向量也相近**。"猫"和"狗"的向量距离近，"猫"和"苹果"的距离远。这是模型在训练中自己学出来的，不是人手工指定的。

> 术语：一个词的向量叫它的 **Embedding（词嵌入）**。可以理解成"这个词在语义空间里的坐标"。

从这里开始，**文字处理就变成了向量运算**——这是后面一切计算的前提。

## 5. 位置编码

有个关键问题：**注意力是并行的，它天然不知道"顺序"**。

对注意力来说，"我打你"和"你打我"里的三个词一模一样，只是顺序不同——可意思完全相反。如果不管顺序，模型会分不清这两句。

解决办法：**在词向量里"掺入"位置信息**，给每个位置一个独特的"座位号向量"，加到词向量上：

```
"我"(位置0) → 词向量 + 位置0向量
"打"(位置1) → 词向量 + 位置1向量
"你"(位置2) → 词向量 + 位置2向量
```

> 类比：给一排士兵发编号，1 号、2 号、3 号……每个人既知道"自己是谁"（词），也知道"自己站第几"（位置）。

这样，同样的词出现在不同位置，就会得到**不同的向量**，顺序信息就保住了。

## 6. 注意力 Attention

**这是 Transformer 的灵魂，请重点看这一节。**

### 6.1 先给一个生活类比

想象你在搜索引擎里搜"红烧肉怎么做"：

- **Query（查询 Q）**：你脑子里的问题——"我想知道红烧肉的做法"。
- **Key（键 K）**：每个网页的**标题/标签**——用来判断"这个网页是不是在讲红烧肉"。
- **Value（值 V）**：每个网页的**正文内容**——真正有用的信息。

搜索引擎做的事：拿你的 Query 去和每个网页的 Key 比对，**相关度越高，就越重点采用那个网页的 Value**。

### 6.2 Attention 就是"带权重的取信息"

Transformer 的注意力一模一样，只是发生在"一句话内部"：

- 每个词都生成自己的 **Q、K、V** 三个向量。
- 某个词想知道"我该重点看谁"，就用自己的 **Q** 去和所有词的 **K** 算相关度（点积）。
- 相关度经过 `softmax` 归一化成"权重"（总和为 1，可以当概率看）。
- 最后用权重对所有词的 **V** 做**加权求和**，得到"这个位置融合了上下文信息的新表示"。

```
Attention(Q, K, V) = softmax( Q·Kᵀ / √d ) · V
                       └──算相关度──┘ └──按相关度加权取信息──┘
```

（`√d` 是缩放因子，防止数字太大导致 softmax 梯度消失，属工程细节，可忽略。）

### 6.3 一个具体的数字例子

句子：**"The cat sat on the mat"**（猫坐在垫子上）

现在我们要理解 "cat" 这个词。自注意力会让 "cat" 的 **Q** 去和每个词（包括自己）的 **K** 比对，算出相关度，再 softmax 成权重：

| 词 | 和 "cat" 的相关度 | softmax 后的权重 |
| --- | --- | --- |
| The | 低 | 0.03 |
| **cat** | 高（自己） | **0.45** |
| **sat** | 很高（猫在做"坐"这个动作） | **0.35** |
| on | 低 | 0.05 |
| the | 低 | 0.02 |
| mat | 中（猫坐在"垫子"上） | 0.10 |

于是 "cat" 的新表示 = `0.03×V_The + 0.45×V_cat + 0.35×V_sat + ...`，它**融合了 "sat" 和 "mat" 的信息**——模型就"知道"了：这只猫是"坐在垫子上"的那只，而不是随便一只猫。

> 这就是"注意力"字面意思的由来：模型把注意力**分配**给了最相关的词（sat、mat），而不是平均地看所有词。

### 6.4 自注意力 Self-Attention

上面的例子叫**自注意力**：**Q、K、V 都来自同一句话内部**——每个词都和"自己这一句话里"的所有词算相关度。这是 Transformer 最常用的一种注意力。

> 记忆点：**自注意力 = 句子里每个词都向其他词"打听"信息，并按相关度加权融合。**

### 6.5 多头注意力 Multi-Head

一个问题：单次注意力可能只关注**一个角度**（比如语法关系），但语言是立体的，既有关联也有指代、语气等多重关系。

**多头（Multi-Head）** 的思路：**同时做多组独立的注意力**，每组关注不同角度，最后把结果拼起来。

```
        ┌─ 头1：关注"语法主谓关系"
输入 ────┼─ 头2：关注"指代/共指"（它=小明）
        ├─ 头3：关注"语义搭配"
        └─ 头4：关注"词义相关"
        ...（论文用了 8 个头）
```

> 类比：一个专家委员会，8 个专家从 8 个角度审视同一句话，最后把意见汇总。每个"头"都有自己的 W_Q、W_K、W_V 权重，各学各的。

## 7. 注意力之外的两个配角

一个 Transformer 层除了注意力，还有两个固定配件，理解它们就能看懂架构图。

### 7.1 前馈网络 FFN

每个词的向量，**独立地**经过一个小的全连接网络（两层 MLP），做一次特征变换。它**不跨词交流**（跨词交流是注意力的事），只是把每个位置的信息再加工一遍。

> 类比：注意力负责"词与词之间的沟通"，FFN 负责"每个词自己消化、加工信息"。

### 7.2 残差连接 + 层归一化

架构图里每条支路都有 `Add & Norm` 两个小方块：

- **残差连接（Add）**：把输入原样**抄近道**加到输出上：`输出 = 输入 + 注意力/FFN的结果`。作用是防止深层网络"梯度消失"，让信息能一路畅通传到底层。
- **层归一化（LayerNorm）**：把数值范围拉回一个稳定的尺度，让训练更稳定、更快收敛。

> 类比：残差像高速公路的**应急车道**，堵车（梯度消失）时信息还能绕过去；LayerNorm 像给数据**统一度量衡**，避免数值忽大忽小。

## 8. Encoder 和 Decoder 怎么配合

现在把积木拼起来看完整流程（以翻译 "I love you" → "我爱你" 为例）：

```
Encoder（理解输入）
  "I" "love" "you"
    ↓ 自注意力（词之间互相看）
    ↓ FFN + 残差 + 归一化
    ↓ × N 层重复
    ↓
  产出：三个"装满了整句上下文"的向量  ← 这就是 Encoder 的"理解结果"

Decoder（生成输出）
  已经生成："我 爱"
    ↓
  ① 带掩码的自注意力：只允许看"已经生成的词"，不能偷看未来
    ↓
  ② 交叉注意力：用 Decoder 的 Q 去查 Encoder 的 K、V  ← 关键！这就是"看着原文来翻译"
    ↓
  ③ FFN + 残差 + 归一化
    ↓
  输出：下一个词"你"
```

两个注意力的区别，务必分清：

| 类型 | Q 来自 | K、V 来自 | 作用 |
| --- | --- | --- | --- |
| **自注意力** | 自己 | 自己 | 看自己这层/这句话内部的词 |
| **交叉注意力（Cross-Attention）** | Decoder | Encoder | 生成时"回头参考"输入原文 |

> 一句话记忆：**Encoder 用自注意力读懂输入；Decoder 用带掩码的自注意力"看已生成"，再用交叉注意力"回头看原文"。**

## 9. 训练和推理的区别

这是理解"大模型为什么会一本正经地胡说"的关键，也顺便讲清楚 **Mask（掩码）** 是干嘛的。

### 9.1 训练：开卷考试（Teacher Forcing）

训练时，**答案是已知的**。给定一句完整的话，模型被要求："看到前面几个词，猜出下一个词"，然后和标准答案比对、纠正权重。

但这里有个作弊风险：Decoder 的自注意力会**看到后面的词**（因为输入是完整的）。所以必须给它戴上"眼罩"——**Mask（掩码）**：

```
已知句子："我 爱 你"
预测"爱"这个位置时，只允许看 ["我"]，把 "爱"、"你" 挡住（mask 掉）
预测"你"这个位置时，只允许看 ["我","爱"]，把 "你" 挡住
```

> 掩码 = 让模型**只能向左看，不能向右看**，防止"用未来的答案来预测未来"。

### 9.2 推理：闭卷生成（自回归）

真正用的时候（比如你问 ChatGPT 问题），答案是未知的。模型只能：

1. 拿到你的问题；
2. 生成第一个词；
3. 把第一个词接回去，再生成第二个词；
4. ……如此循环，一个词一个词地"吐"，直到生成结束标记。

这就是**自回归（Autoregressive）**，也是为什么大模型回答是**一个字一个字"流式"蹦出来**的原因——它每生成一个词都要回头重算一遍注意力。

## 10. 为什么 ChatGPT 只用一半

你可能听过："GPT 是 Decoder-only（只用解码器）"。为什么把 Encoder 扔了？

因为 **Encoder-Decoder 是为"翻译"这种"输入一个序列、输出另一个序列"设计的**。而 ChatGPT 干的事本质只有一个：

> **给定一段文字，续写下去（预测下一个词）。**

这种"续写"任务，**只需要自回归的 Decoder 就够了**——Encoder 那种"先整体理解再另起炉灶输出"的中间表示不是必需的。

所以 GPT 系列（以及现在的绝大多数大模型）**只保留 Decoder 那半边**，把"交叉注意力"也去掉（因为没有 Encoder 可看了），剩下的就是：

```
输入文本 → 词嵌入 + 位置编码 → [ 带掩码的自注意力 + FFN ] × 很多很多层 → 预测下一个词
```

层数从论文的 6 层暴涨到几百层，参数量从 6500 万暴涨到几千亿，但**基本积木块没变**——还是那三样：**自注意力 + FFN + 残差归一化**。

> 这也是为什么前面几节值得吃透：看懂那三样积木，你就看懂了大模型的"心脏"。

## 11. 总结

### 一张全景图（最小可运行版本）

```
              输入句子（一批 token）
                     │
             词嵌入 + 位置编码
                     │
        ┌────────────▼────────────┐
        │  多头自注意力            │◄── 每个词看所有词，算相关度、加权融合
        ├─────────────────────────┤
        │  + 残差 & 层归一化        │
        ├─────────────────────────┤
        │  前馈网络 FFN            │◄── 每个词独立做特征加工
        ├─────────────────────────┤
        │  + 残差 & 层归一化        │
        └────────────┬────────────┘
                     │   （这个块重复 N 层）
                     ▼
              输出：每个词"装满了上下文"的向量
                     ▼
              预测下一个词（GPT）或接 Decoder（翻译）
```

### 核心概念速查表

| 概念 | 一句话解释 |
| --- | --- |
| Token | 文本的最小单元（词或子词），一切计算的输入 |
| 词嵌入 Embedding | 把词变成向量，语义相近的向量也相近 |
| 位置编码 | 给向量掺入位置信息，弥补注意力"不懂顺序" |
| 注意力 Attention | 用 Q 查 K，按相关度加权取 V，实现"重点看谁" |
| 自注意力 Self-Attention | Q/K/V 都来自同一句话内部 |
| 多头 Multi-Head | 多组注意力并行，从不同角度观察 |
| 交叉注意力 Cross-Attention | Decoder 的 Q 去查 Encoder 的 K/V，生成时参考原文 |
| 掩码 Mask | 挡住未来，防止偷看答案 |
| 前馈网络 FFN | 每个词独立做特征变换 |
| 残差连接 | 抄近道，防止梯度消失 |
| 层归一化 LayerNorm | 统一数值尺度，稳定训练 |
| Softmax | 把一堆分数变成"和为 1 的权重" |
| 自回归 | 一个词一个词地生成，用上一个词预测下一个 |

---

## 结语

回到开头那句话：**Transformer 就是一个"看上下文、猜下一个词"的机器，核心是注意力——让每个词自己去判断"我该重点看谁"。**

如果你只想记住三件事，记住这三件就够：

1. **注意力**是灵魂：Q 查 K、按相关度加权取 V。
2. **自注意力 + FFN + 残差归一化**，是反复堆叠的唯一积木。
3. **训练是开卷（带掩码防作弊），推理是闭卷（自回归一个个吐词）**。

其余的多头、位置编码、LayerNorm 都是"让这三件事跑得更稳、更细"的优化。吃透这三条，去看任何大模型的科普或源码，都不会再晕。
