# 08 权限、安全与隐私：从 requestPermission 到 AppOps 和合规边界

> App 权限问题不能只看 manifest。现代 Android 还涉及运行时授权、AppOps、前台服务类型、分区存储、PendingIntent 安全、Deep Link 暴露和隐私合规。

---

## 1. 权限链路总览

```text
AndroidManifest.xml 声明权限
  -> 安装时 PMS 解析
      -> 运行时 requestPermissions
          -> PermissionController 展示弹窗
              -> PermissionManagerService 记录授权状态
                  -> AppOpsService 参与运行时操作控制
```

App 侧看起来是：

```kotlin
val launcher = rememberLauncherForActivityResult(
    ActivityResultContracts.RequestPermission(),
) { granted ->
    if (granted) startCamera() else showPermissionDenied()
}

Button(onClick = { launcher.launch(Manifest.permission.CAMERA) }) {
    Text("Open camera")
}
```

源码要结合：

- `PackageManagerService`
- `PermissionManagerService`
- `AppOpsService`
- `PermissionController` App

## 2. Manifest 权限和运行时权限

声明：

```xml
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

运行时检查：

```kotlin
fun Context.hasPermission(permission: String): Boolean {
    return ContextCompat.checkSelfPermission(this, permission) == PackageManager.PERMISSION_GRANTED
}
```

Activity Result API：

```kotlin
private val requestCamera = registerForActivityResult(
    ActivityResultContracts.RequestPermission(),
) { granted ->
    if (granted) openCamera() else showCameraDeniedDialog()
}
```

注意：用户拒绝后不要无限弹窗。要根据业务解释权限用途，并提供降级路径。

## 3. AppOps：有权限也可能不可用

权限是“能不能声明和授权”，AppOps 更像“这次操作能不能执行”。

典型现象：

- 定位权限已授权，但后台定位被限制。
- 悬浮窗权限不是普通运行时权限。
- 通知权限、精确闹钟、使用情况访问有独立开关。

排查：

```bash
adb shell appops get package.name
adb shell dumpsys package package.name
```

App 侧跳转设置页：

```kotlin
val intent = Intent(Settings.ACTION_APPLICATION_DETAILS_SETTINGS).apply {
    data = Uri.fromParts("package", packageName, null)
}
startActivity(intent)
```

## 4. 通知权限和前台服务类型

Android 13+ 通知需要：

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

Android 14+ 前台服务类型更严格：

```xml
<service
    android:name=".LocationService"
    android:foregroundServiceType="location" />

<uses-permission android:name="android.permission.FOREGROUND_SERVICE_LOCATION" />
```

启动前台服务：

```kotlin
ContextCompat.startForegroundService(context, Intent(context, LocationService::class.java))
```

Service 内：

```kotlin
override fun onCreate() {
    super.onCreate()
    startForeground(NOTIFICATION_ID, buildNotification())
}
```

## 5. 分区存储和媒体权限

Android 13+ 媒体权限拆分：

- `READ_MEDIA_IMAGES`
- `READ_MEDIA_VIDEO`
- `READ_MEDIA_AUDIO`

优先使用系统 Photo Picker：

```kotlin
val picker = rememberLauncherForActivityResult(
    ActivityResultContracts.PickVisualMedia(),
) { uri ->
    if (uri != null) handleImage(uri)
}

picker.launch(PickVisualMediaRequest(ActivityResultContracts.PickVisualMedia.ImageOnly))
```

这样很多场景不再需要读取整个相册权限。

## 6. PendingIntent 安全

Android 12+ 必须声明 mutability：

```kotlin
val pendingIntent = PendingIntent.getActivity(
    context,
    0,
    Intent(context, DetailActivity::class.java),
    PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE,
)
```

原则：

- 默认用 `FLAG_IMMUTABLE`。
- 需要系统或外部填充内容时才用 `FLAG_MUTABLE`。
- Intent 尽量显式指定 component/package。

## 7. Deep Link 安全

manifest：

```xml
<activity
    android:name=".DetailActivity"
    android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.VIEW" />
        <category android:name="android.intent.category.DEFAULT" />
        <category android:name="android.intent.category.BROWSABLE" />
        <data android:scheme="https" android:host="example.com" />
    </intent-filter>
</activity>
```

Activity 内必须校验参数：

```kotlin
fun parseArticleId(intent: Intent): String? {
    val uri = intent.data ?: return null
    if (uri.host != "example.com") return null
    return uri.getQueryParameter("id")?.takeIf { it.matches(Regex("[0-9]+")) }
}
```

不要把未校验参数直接用于文件路径、WebView URL、支付参数或内部页面跳转。

## 8. WebView 安全

```kotlin
webView.settings.javaScriptEnabled = true
webView.settings.allowFileAccess = false
webView.settings.allowContentAccess = false
webView.webViewClient = object : WebViewClient() {
    override fun shouldOverrideUrlLoading(view: WebView, request: WebResourceRequest): Boolean {
        val host = request.url.host
        return host !in trustedHosts
    }
}
```

重点：

- JS Bridge 暴露面要小。
- 不加载不可信本地文件。
- URL 跳转要校验域名。
- 支付、登录态、Token 不要直接拼进 URL。

## 9. Keystore 和敏感数据

```kotlin
val masterKey = MasterKey.Builder(context)
    .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
    .build()

val encryptedPrefs = EncryptedSharedPreferences.create(
    context,
    "secret",
    masterKey,
    EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
    EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM,
)
```

注意：本地加密降低泄漏风险，但不能把客户端当成绝对可信环境。服务端仍要做鉴权和风控。

## 10. 常见问题

| 问题 | 优先排查 |
|---|---|
| 有权限但定位失败 | AppOps、后台定位、系统定位开关 |
| 通知不显示 | 通知权限、channel、SystemUI、勿扰模式 |
| 前台服务崩溃 | service type、权限、startForeground 超时 |
| 相册读取失败 | Android 版本、媒体权限、Photo Picker |
| Deep Link 打开异常 | exported、intent-filter、参数校验 |
| WebView 风险 | JS Bridge、URL 白名单、mixed content |
