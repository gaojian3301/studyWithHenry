# 07 网络与数据存储：Retrofit、OkHttp、Room、DataStore 与缓存策略

> App 的业务稳定性很大一部分来自数据层。网络失败、缓存不一致、数据库迁移失败、文件权限变化，都会直接变成用户可见问题。

---

## 1. 数据层常见结构

```text
Repository
  ├─ RemoteDataSource: Retrofit / OkHttp / WebSocket
  ├─ LocalDataSource: Room / DataStore / File
  └─ Mapper: DTO <-> Entity <-> Domain
```

推荐不要让 UI 直接拿 DTO，也不要让 Retrofit response 泄漏到页面层。

## 3. OkHttp 拦截器

认证拦截器：

```kotlin
class AuthInterceptor(
    private val tokenProvider: TokenProvider,
) : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val token = tokenProvider.currentToken()
        val request = chain.request().newBuilder()
            .apply { if (token != null) header("Authorization", "Bearer $token") }
            .build()
        return chain.proceed(request)
    }
}
```

刷新 Token 建议用 `Authenticator`：

```kotlin
class TokenAuthenticator(
    private val tokenRepository: TokenRepository,
) : Authenticator {
    override fun authenticate(route: Route?, response: Response): Request? {
        if (responseCount(response) >= 2) return null
        val newToken = tokenRepository.refreshBlocking() ?: return null
        return response.request.newBuilder()
            .header("Authorization", "Bearer $newToken")
            .build()
    }
}
```

源码入口：

- `RealCall`
- `RealInterceptorChain`
- `RetryAndFollowUpInterceptor`
- `CacheInterceptor`

## 4. 统一错误处理

```kotlin
suspend fun <T> apiCall(block: suspend () -> T): ApiResult<T> {
    return try {
        ApiResult.Success(block())
    } catch (error: UnknownHostException) {
        ApiResult.NetworkError
    } catch (error: SocketTimeoutException) {
        ApiResult.Timeout
    } catch (error: HttpException) {
        ApiResult.HttpError(error.code(), error.response()?.errorBody()?.string())
    } catch (error: CancellationException) {
        throw error
    } catch (error: Throwable) {
        ApiResult.Unknown(error)
    }
}
```

注意 `CancellationException` 必须继续抛出。

## 5. Room 和缓存优先策略

常见策略：页面观察本地数据库，同时触发网络同步。

```kotlin
class NewsRepository(
    private val api: NewsApi,
    private val dao: NewsDao,
) {
    fun observeNews(): Flow<List<News>> {
        return dao.observeAll().map { list -> list.map { it.toDomain() } }
    }

    suspend fun refresh() {
        val remote = api.getNews()
        dao.withTransaction {
            dao.clear()
            dao.insertAll(remote.map { it.toEntity() })
        }
    }
}
```

优点：页面打开立即显示缓存，网络回来后数据库更新，Flow 自动刷新 UI。

源码入口：

- `RoomDatabase#withTransaction`
- `InvalidationTracker`
- 生成 DAO 实现

## 6. 数据库迁移

```kotlin
val MIGRATION_1_2 = object : Migration(1, 2) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("ALTER TABLE users ADD COLUMN avatarUrl TEXT")
    }
}

Room.databaseBuilder(context, AppDatabase::class.java, "app.db")
    .addMigrations(MIGRATION_1_2)
    .build()
```

迁移测试：

```kotlin
@Test
fun migrate1To2() {
    helper.createDatabase(TEST_DB, 1).apply { close() }
    helper.runMigrationsAndValidate(TEST_DB, 2, true, MIGRATION_1_2)
}
```

数据库迁移是必须测试的点，因为线上失败就是 App 启动崩溃。

## 7. DataStore 存配置

适合保存小型配置：开关、用户偏好、本地标记。

```kotlin
class SessionStore(
    private val dataStore: DataStore<Preferences>,
) {
    private val tokenKey = stringPreferencesKey("token")

    val token: Flow<String?> = dataStore.data.map { it[tokenKey] }

    suspend fun saveToken(token: String) {
        dataStore.edit { it[tokenKey] = token }
    }

    suspend fun clear() {
        dataStore.edit { it.remove(tokenKey) }
    }
}
```

不要用 DataStore 存大列表或复杂关系数据，那是数据库的职责。

## 8. 文件、MediaStore 和 SAF

Android 10 后分区存储改变了文件访问方式。

常见选择：

| 场景 | 建议 |
|---|---|
| App 私有文件 | `context.filesDir` / `cacheDir` |
| 图片视频写入相册 | MediaStore |
| 用户选择任意文档 | Storage Access Framework |
| 分享文件给其他 App | FileProvider |

MediaStore 写图片：

```kotlin
val values = ContentValues().apply {
    put(MediaStore.Images.Media.DISPLAY_NAME, "photo.jpg")
    put(MediaStore.Images.Media.MIME_TYPE, "image/jpeg")
    put(MediaStore.Images.Media.RELATIVE_PATH, Environment.DIRECTORY_PICTURES)
}

val uri = resolver.insert(MediaStore.Images.Media.EXTERNAL_CONTENT_URI, values)
requireNotNull(uri)
resolver.openOutputStream(uri)?.use { output -> bitmap.compress(Bitmap.CompressFormat.JPEG, 92, output) }
```

## 9. 常见问题

| 问题 | 排查方向 |
|---|---|
| Retrofit 返回解析失败 | DTO 字段、空值、序列化配置 |
| Token 刷新死循环 | Authenticator 重试次数、并发刷新锁 |
| 数据刷新后 UI 不变 | Room 查询是否 Flow、事务是否提交 |
| 数据库迁移崩溃 | migration 缺失、schema 不匹配 |
| 文件写入失败 | 分区存储、权限、URI 授权 |

## 10. 源码查看建议

1. Retrofit 动态代理如何把接口方法变成 HTTP 请求。
2. OkHttp 拦截器链如何执行。
3. Room 生成 DAO 如何封装 SQL。
4. Room InvalidationTracker 如何通知 Flow。
5. DataStore 如何串行写入。
6. ContentResolver 如何写 MediaStore。

网络和存储源码不要分开看。实际问题通常发生在“网络返回 -> 映射 -> 入库 -> Flow 通知 -> UI 刷新”这一整条链上。
